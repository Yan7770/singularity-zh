本次优化的对象是 singularity-bilingual（双语版静态站点）。原站以 React 构建产物 + 一层 25 KB 翻译脚本的方式发布，视觉语言本身已经很强——奶油纸底色、Instrument Serif 的编辑体标题、等宽微标签、墨绿强调色。问题不在审美方向，而在执行精度：跨断点的排版不收敛、状态与反馈缺位、双语两套排印互相打架。以下先梳理结构与问题，再逐项说明调整方向与预期效果。

范围 · 8 个区块 / 150 条文案 / 2 种语言 断点 · 1440 · 1024 · 900 · 640 · 390 约束 · 品牌风格与功能逻辑不变

01当前站点的结构与实现方式

原站是单页滚动式站点，语义上分为 10 个纵向区块，全部由 React 运行时渲染进 #root：

序区块作用主要组件
—Header（fixed）品牌、四项导航、主 CTA吸顶栏 / 深色区反色
—Hero主张、双 CTA、事件视界图版、三项指标Canvas + SVG 覆盖层
01Doctrine信条陈述 + 定义 / 诊所 / 使命三栏逐词显现长段落
02Instruments四台仪器四栏等分卡片
03Protocol十二周五步流程左栏粘性 + 右侧时间轴
04Telemetry连续监测（深色区）三标签 + 实时波形面板
05Outcomes四项队列指标计数动画
06Journal三篇文章CSS 渐变缩略图卡片
—Quote / Membership / Footer会员证言、申请表单、巨型字标表单 + 手风琴式页脚

实现层面的关键事实，决定了优化的做法：

  • 样式是 Tailwind 的压缩产物（app.css 33 KB，单行），类名以任意值形式内联（如 text-[8.5px]、tracking-[0.22em]），没有可复用的设计令牌层。
  • 文案靠 遍历 DOM 文本节点替换（i18n.js），依赖「英文原文」作为哈希键；任何文案微调都会让对应词条失配。
  • 动效由 IntersectionObserver 逐个元素驱动，非统一节流。
结论：在压缩产物上叠样式覆盖只能治表——排版断点、标题层级、状态反馈这些都是结构问题。因此本次按同一视觉语言重建为无框架静态站（1 HTML + 1 CSS + 1 JS），把令牌、组件、动效收进一套可维护的体系，并保留全部内容与交互逻辑。

03优化方向与预期效果

一 · 视觉界面

1 建立令牌层，替换任意值

调整：把颜色、字号、间距、动效收敛为 :root 变量，屏幕尺寸变化时用 clamp() 连续插值，而不是靠一串断点硬跳。版心固定 78rem，左右留白 clamp(20px, 4.5vw, 56px)。

预期：同一组件在任何宽度下比例一致；后续改一处即可全站生效，不再出现 8.5px 这类失控值。

2 深色区改为令牌反转，而非覆盖

调整：遥测区只重声明 --ink / --paper / --line 等变量，组件本身不写第二套深色规则。头部通过 data-on-dark 同步反转，并改用下缘渐隐的磨砂遮罩替代整块实色面板。

预期：彻底消除深/浅交界处的硬边色块，导航文字在深底上保持可读；新增深色区块无需再写样式。

3 版面节奏与对齐规则

调整：每个区块统一「编号眉标 + 顶部细线 + 标题区」骨架；三栏文字的基线与细线取齐；卡片用 flex 把脚注压到底部；期刊卡片给标题预留两行高度，使日期行跨卡对齐；指标数字启用 font-variant-numeric: tabular-nums。

预期：并排元素无需目测就能对齐；计数动画过程中数字不抖动、不与单位重叠。

4 组件样式收敛

调整：按钮统一为「墨色实心 / 描边」两级，同高 48 px，移动端等宽满行；表单从冷蓝渐变改为暖白纸面，输入框保留常驻下划线并在聚焦时加深；微标签下限提至 11 px。

预期：主次动作一眼可辨；表单可填写性明显提升，不再像装饰性占位。

5 响应式重建

调整：900 px 以下收起导航进入全屏菜单；640 px 以下首屏改为单列，指标条改为「标签左 / 数值右」的对照行；卡片、指标、页脚依次降列，最小点击区 44 px。

预期：390 px 下无横向滚动、无截断、无挤压；拇指可点区域达标。

二 · 文本内容

6 动词统一

调整：一个动作一种说法——导航与首屏统一 Request an introduction（中：申请引荐），表单按钮保留 Submit request（提交申请），成功后按钮变为 Request received（已收到）。

预期：用户不必判断「这三个按钮是不是同一件事」。

7 层级命名与栏目语义

调整：眉标统一「编号 — 名称」；页脚三列改为 Practice（科学/仪器/流程/期刊）、Access（会员/医生/驻留/联系）、Legal，栏目名与条目对齐；无对应页面的法务项不再伪装成链接，改为带点线下划的占位项。

预期：信息架构自洽，杜绝「点了跳到页首」的挫败。

8 单位与符号的一致性

调整：卡片脚注统一 值 · 限定词（3.2 Gb · 60× depth / 1,400 signals · daily / 0.4 μm · sub-cellular / 1 physician · 22 members）；技术符号关闭 text-transform: uppercase，避免 μm 被渲染成 ΜM、λ 变成 Λ。

预期：专业读者不会读到错误单位，视觉上也更克制。

9 中文排印单独调校

调整：汉字场景把字距从 0.16–0.22em 降到 0.06em；正文行高提到 1.9；标题行高 1.28；斜体在中文下改为字重强调（消除伪斜）；断句按标点切分，避免长句中段被生硬断开。

预期：中文不再是「英文版式套汉字」，阅读节奏接近原生中文编辑排版。

10 补齐状态文案

调整：新增必填 / 格式错误 / 发送中 / 成功 / 失败五类文案（中英各一套），错误就近显示并写明期望格式。

预期：用户永远知道「刚才那一下发生了什么、下一步做什么」。

三 · 动效交互

11 动效令牌

调整：时长固定三档 180 / 380 / 720 ms，缓动统一 cubic-bezier(.22,.61,.36,1)；入场用 translateY(14px)+opacity，位移量与字号无关。

预期：全站节奏一致，不再有「有的地方弹、有的地方顿」。

12 逐词显现重写

调整：词以 inline-block 包裹并在其间保留真实空格，用 CSS 变量做级联延迟；中文按标点切成语块。

预期：修复移动端「Theendof」粘连；同一机制在中英两种语言下都成立。

13 悬停与滚动反馈

调整：卡片悬停仅改底色与图标色（180 ms）；箭头位移 2 px；期刊「阅读」字样随悬停淡入；导航下划线从左展开；当前区块自动标记。

预期：反馈可见但不喧哗，符合品牌克制的语气。

14 画布性能

调整：事件视界图版与心电波形均以 IntersectionObserver 控制启停，DPR 上限 2，离屏即停；prefers-reduced-motion 下渲染静态帧。

预期：滚动到其他区块时 CPU 归零；低端设备不因画布掉帧。

15 加载与状态

调整：提交时按钮进入 spinner + 文案切「发送中」，完成后整块转入完成态并播报成功（aria-live）；首屏元素分级入场，标题先于说明文字。

预期：表单从「黑盒」变为可感知的过程；首屏建立视觉重心的顺序更自然。

04设计规范（三组参考色）

第二轮把三组参考色落成一套有明确分工的色板：柔奶白作纸底，捣蓝色作正文与深色区，深海蓝作结构性强调，清水蓝作浅色块，甜酷粉只留给信号点。

--ink捣蓝色 #113056
--accent深海蓝 #122E8A
--tint清水蓝 #91CFD5

拉丁保留 Instrument Serif（标题）、Inter（正文）、IBM Plex Mono（微标签）。中文在第二轮换掉了系统回退：Windows 上原先落到宋体，标题笔画发旧；现改为 Noto Serif SC（400/500 两字重），只在衬线场景生效，正文中文仍走系统黑体（苹方 / 微软雅黑），避免为正文付中文字库的代价。

Noto Serif SC 由 Google Fonts 按 unicode-range 切片，浏览器只下载页面实际用到的那几片，而不是整包 1–3 MB。这是「标题用真衬线、正文不背字库」的折中。
